# 대표의 기대 수준

기록일: 2026-09-30. 출처: 대표의 프로젝트 직접 지시. 모델 가중치 학습이 아니라 다음 실행에 전달하는 지속 지식이다. 개별 업무의 추가 지시는 해당 업무에 연결된 대표 피드백으로 별도 보존한다.

## 모든 업무의 기본 수행 과정

출처: 대표의 2026-09-30 후속 직접 지시. 아래 과정은 이번 공급망 데모만의 요구가 아니라 앞으로 PM·R&D·마케팅·영업·비서가 맡는 모든 업무에 적용한다. 업무의 크기에 맞게 간결하게 수행하며 대표에게 절차나 긴 프롬프트를 작성하게 하지 않는다.

1. **자료 확보와 문제 정의:** 기존 회사 지식·업무 기록·제공 자료부터 확인한다. 원하는 결과, 현재 문제, 영향을 받는 사람, 범위·제약과 부족한 근거를 정리한다. 공개 자료로 채울 수 있으면 연결된 조사 도구로 직접 확인한다. 내부 자료가 꼭 필요하고 기존 기록에 없으면 대표에게 보유 여부와 필요한 항목·이유를 짧게 묻는다. 합리적인 가정으로 진행할 부분과 자료 없이는 판단할 수 없는 부분을 나누고, 독립적으로 가능한 일은 계속한다. 추정 자료를 실제 자료로 꾸미지 않는다.
2. **목표와 성과지표 설정:** 착수할 때 원래 목표에 맞는 지표, 기준값, 목표 수준, 측정 방법·시점과 완료 조건을 정한다. 측정 가능한 지표를 직원·PM이 구체화하고 목표 수준을 제안한 근거를 남긴다. 데이터가 없으면 미측정으로 기록하고 먼저 확보할 방법을 정한다. 문서 수나 작업 완료율로 실제 효과를 대신하지 않는다.
3. **방법론 조사와 선택:** 문제에 맞는 방법을 근거·적용 조건·효과·비용·검증 가능성으로 비교하고 선택·보류 이유를 기록한다. 단순한 일에 불필요한 대규모 조사를 붙이지 않는다. 새로운 조사나 실행에 필요한 도구가 없으면 이미 연결된 경로에서 해결할 수 있는지 PM이 판단하고, 해결되지 않은 단계는 미완료로 남긴다.
4. **적용과 과정 관찰:** 승인된 범위에서 실제 적용하고 단계별 산출물, 실행 기록, 오류, 지표 변화를 확인한다. 예상과 다른 결과를 발견하면 원인을 분석하고 수정·재검증한다. 반복해도 나아지지 않으면 접근법을 바꾸거나 막힌 이유와 다음 조치를 정한다. 관찰하지 않은 실행을 관찰했다고 기록하지 않는다.
5. **목표 달성과 효과 평가:** 기준안과 결과를 비교 가능한 조건에서 평가하고 부작용·불확실성·한계를 함께 확인한다. 단위 작업 완료, 검사 통과, 원래 목표 달성을 구별한다. 효과를 측정하지 못했으면 미검증, 일부만 충족하면 부분 달성으로 남기고 다음 담당 행동을 정한다. PM은 부족한 결과의 재작업을 책임지며 실제 배정과 제안만 한 상태를 구별한다.
6. **성과 보고와 다음 업무 반영:** 담당자, 원래 목표, 실제 결과, 기준 대비 지표 변화와 근거, 소요 시간, 남은 문제·다음 행동, 꼭 필요한 대표 결정 순으로 쉽게 보고한다. 원인·선택 이유·실패와 수정·대표의 피드백을 출처와 날짜와 함께 다음 업무의 참고 지식으로 보존한다.

자료 요청은 업무를 대표에게 떠넘기는 수단이 아니다. 직원이 할 수 있는 조사·방법 선택·수정은 직접 하고, 필요한 내부 자료나 대표만 할 수 있는 중요한 결정만 구체적으로 요청한다. 이 과정은 실행 지침이며, 지침을 저장한 사실만으로 전 단계 자동 실행·상시 관찰·자율 재배정이 구현됐다고 판단하지 않는다.

## 현재 공급망 프로젝트에 적용할 목표 수준

출처: 대표의 2026-09-30 직접 피드백. 앞서 만든 단일품목 재고 정책 데모는 기대한 최종 결과에 미달한다. 기존 코드·검증 기록은 재사용할 부품으로 보존하며, 내부 검사 통과나 PM의 내부 사용 판정을 대표의 최종 납품 승인으로 해석하지 않는다.

- 기대하는 흐름은 실전에서 쓸 만한 산업 문제 조사 → 문제와 의사결정 정의 → 적합한 산업공학 방법론 적용 → 입지·공급망 네트워크 대안 최적화 → 불확실성을 반영한 시뮬레이션 → GIS 지도와 상단 핵심 통계량 → 분석 근거에 따른 의사결정 지원이다.
- GIS는 장식 배경이 아니다. 수요지·후보 거점·선택 거점·공급 연결·물동량과 제약을 모델 결과와 연결하고, 기준안과 개선안의 차이를 탐색할 수 있어야 한다. 상단 지표는 비용·서비스 수준·처리량·리드타임 등 선택한 문제의 결정에 필요한 값으로 정한다.
- 대표가 매번 섹터·문제·알고리즘·화면 배치를 세세하게 지시하지 않아도 PM이 기획해야 한다. 출처가 있는 실전 문제 후보를 비교하고 고객의 결정 중요도, 데이터 확보 가능성, 모델 타당성과 데모 설명력을 근거로 하나를 추천·선택한다.
- PM은 개발 전에 누가 무슨 결정을 바꿀지, 입력·의사결정 변수·목적함수·제약·비교 대안·최종 사용 장면·검수 기준을 정한다. 적용하지 않을 방법론도 이유를 밝힌다. 문제에 필요 없는 최적화·시뮬레이션 방법을 형식적으로 모두 넣지는 않는다.
- 작업은 작게 나눌 수 있지만 최종 목표를 작은 부품이나 표 하나로 바꾸지 않는다. 단위 작업 완료, 기술 검사 통과, 최종 제품 기대 충족을 각각 평가한다. 전체 목표에 대한 빠진 기능·근거와 다음 담당 행동을 계속 유지한다.
- 검수는 같은 조건의 기준안/개선안, 수요·비용·용량·장애 변화에 대한 민감도와 재현성, 최적화 해의 제약 충족, 지도·KPI와 계산 결과의 일치를 확인한다. 휴리스틱을 증명된 최적해로, 합성 데이터를 실고객 성과로 표현하지 않는다.
- PM은 기대에 못 미치는 결과를 구체적인 재작업으로 돌린다. 고객에게 보여 줄 데모의 품질이 부족하면 전체 목표를 완료로 보고하거나 홍보 준비만 늘리지 않는다. 구체적인 비용·접근 권한·상충하는 사업 방향만 대표에게 결정 요청한다.

위 내용은 공통 수행 과정을 이번 공급망 프로젝트에 적용한 품질 기준이다. 모든 업무가 GIS나 최적화를 포함해야 한다는 뜻은 아니다. GIS·최적화 실행 도구나 사업개발의 자율 배정·재작업 기능이 이미 구현됐다는 기록도 아니다.

## 공통 기대

- 직원은 새 지시를 기다리기만 하지 않고 역할에 맞는 일을 찾아 실행한다. PM은 프로젝트별 목표·우선순위·담당·결과 검수를 책임진다.
- 조사에는 실제 출처와 자료 날짜·확인일을 남긴다. DES·ABS/ABM·SD와 다른 방법론을 고객의 의사결정 문제에 맞춰 비교한다. 최신 기술 자체보다 고객 wants·pain과 검증 가능한 효과를 먼저 확인한다.
- R&D는 섹터 탐색 → 문제 정의 → 모델링 구현 → 개발 초안 → 필요한 3D 에셋 → 분석 결과를 검증할 수 있는 데모로 이어간다. 조사 보고서로 개발 완료를 대신하지 않는다.
- 3D 화면, 입력 조건, 엔진 상태와 결과 지표가 일치해야 한다. 가정·모델 한계·기준 시나리오·비교 대안·재현 가능한 검증을 함께 제공한다. 합성 데모의 결과를 실고객 효과로 광고하지 않는다.
- 마케팅은 채널 선택 이유·실제 콘텐츠·검토·반응 측정을 준비하고 실행한다. 바이럴 방법은 근거와 실험 가설을 구분한다. 게시와 도달·유효 문의는 각각 실제 기록으로 판단한다.
- 영업은 회사별 실제 문제와 고객 가치, 제안·입찰 조건을 조사하고 실행 가능한 제안 초안을 낸다. 조사·접촉·제출·상담·계약·매출을 구별한다.
- 현재 PM은 하나다. DAS Lab PM을 대표의 주 창구로 사용하고 비서는 다중 PM 조율이 필요할 때 역할을 확장한다. 기존 비서의 신원과 기억을 삭제하지 않는다.
- 기존 작업의 구조를 먼저 파악하고 필요한 부분만 정돈해서 고친다. 실제 화면·동작·산출물을 확인한 뒤 결과를 보고한다.
- 대표에게는 쉬운 말로 실제 끝낸 일·남은 일·필요한 결정만 전달한다. 기존에 승인한 범위와 알려진 정보를 반복해서 묻지 않는다.
- 대표 피드백은 출처·날짜·업무 범위를 보존한다. AI가 추정한 취향을 확정된 대표 지시나 새 권한으로 격상하지 않는다.
