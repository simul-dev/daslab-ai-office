## 지금 작업을 이어가는 기준

대표는 여러 PC에서 서로 다른 AI에게 다시 설명하는 부담을 줄이기 위해, 위 로컬 채팅의 작업 이력과 결정 사항을 클라우드에서 이어받고 변경을 커밋·푸시하도록 직접 지시했다. 현재 클라우드 채팅의 지시와 최신 원격 자료를 작업 기준으로 삼는다. PC별 과거 계획이나 미완료 업무는 배경이며 자동으로 재개하지 않는다. 로컬 채팅·PC 파일 재조회를 클라우드 작업 시작의 필수 조건으로 두지 않는다.

이 문서는 작업 맥락을 이어받는 최신 인계 기록이다. `CLOUD-SYNC.md`는 이전 PC의 오래된 작업을 담은 참고 기록으로 유지한다. 두 문서의 상태 표현에는 각각의 기준 날짜가 있으며, 과거 권한이나 일정은 현재 승인으로 자동 적용하지 않는다.

## 대표의 회사 운영 요구

- 목표 조직은 대표 → 전용 비서 → 사업·프로젝트 PM → 전문 리드 → 필요한 임시 전문 에이전트다. 현재 사업 우선순위는 DAS Lab이다.
- **2026-09-30 후속 지시:** PM이 하나인 동안 대표의 실질적인 업무 창구는 DAS Lab PM으로 두고, 전용 비서는 여러 PM을 관리할 때 확장한다. 이는 장기 조직 구상을 삭제한 것이 아니다.
- 대표는 목표와 중요한 조건을 자연어로 전달한다. 책임·세부 계획·담당 배정·완료 기준은 담당 AI가 정리한다. 같은 내용을 여러 직원에게 반복 설명하게 하지 않는다.
- PM은 사전 문제정의와 계획, 실제 배정, 진행·막힘 관찰, 결과 검수, 재작업, 통합 보고까지 책임진다. 다음 할 일을 보고서에 적는 것만으로 실제 위임을 수행했다고 처리하지 않는다.
- 직원의 공통 흐름은 **기존 자료 확인 → 부족한 자료 조사 또는 필요한 내부 자료 요청 → 문제·목표·지표 정의 → 방법 조사·선택·적용 → 진행 관찰·오류 수정·재검증 → 지표로 목표 달성 판단·성과 보고**다.
- 직원 ID·역할·기억·현재 미션·실행 세션·확인된 결과를 구분한다. 현재 담당자 변경으로 제작자·기여자·검수자 기록이 사라져서는 안 된다.
- 구독용 공식 Codex 실행을 사용하며 유료 API 과금으로 자동 전환하지 않는다. 당시 앱의 동시 실행·일일 횟수·시도 횟수 제한은 요금제 제한과 구분한다.
- 현행 대표 지시가 모든 과거 기록보다 우선한다. 과거 음성 방식 변경 요청이나 공개·발송 관련 동의도 날짜·범위가 있는 기록으로 보존하고, 지금 작업의 권한을 새로 만들지 않는다.

## R&D·마케팅·영업의 기대 결과

**R&D:** 기술 동향과 산업의 wants/pain을 탐색하고 DES, ABS/ABM, SD 및 문제에 맞는 방법론을 검토한다. 문제정의 → 모델 구현 → 초안 데모 → 필요한 3D 에셋 → 비교 시나리오 → 모델·화면 검증으로 발전시킨다. 조사 보고서만 반복하는 정기업무는 기대에 미달한다.

공급망에 대한 대표의 구체 기대는 **현실적인 산업 문제 조사 → 입지·네트워크 최적화 → 변동 상황 시뮬레이션 → GIS 지도와 상단 핵심 지표로 대안 비교 → 의사결정 지원**이다. 합성 데이터의 재고 실험이나 작은 시험용 HTML을 고객용 완성 데모로 보고하지 않는다.

**기획·마케팅:** 실제 데모와 기술력에 근거해 채널을 선택하고, 콘텐츠 기획·제작·검토와 SNS 확산 가설·반응 측정까지 연결한다.

**영업지원:** 잠재 고객·입찰·협력 기회를 공식 자료로 찾고, 고객 가치와 조건 적합성을 검토해 제안 자료를 만든다. 실제 게시·고객 연락·입찰 제출 여부는 초안 준비와 구분한다.

원래의 데모 고도화·전체 9개 데모 홍보 미션은 유지한다. 시험 업무나 문서 작성만으로 사업 목표가 완료됐다고 기록하지 않는다.

## UI와 PM 보고의 확정 방향

대표가 보고 싶은 것은 보고서 분량보다, 누가 어떤 목표로 무엇을 만들었고 무엇이 달라졌는지 한눈에 확인하는 화면이다.

- **회사 현황:** 조직별 성과, 주요 프로젝트, 막힌 일, 필요한 결정.
- **프로젝트:** 목표, 책임 PM, 직원별 업무·진행·산출물.
- **산출물:** 제작자·기여자·제작 목적·날짜·버전·검수 상태·사용 방법·실행 버튼.
- **PM 보고:** 문제 → 직원별 기여 → 결과 비교와 지표 → 검수 → 남은 일·다음 결정. 원본 자료로 이어지는 시각적인 스토리보드.
- Paperclip의 상태와 실제 실행 기록을 사무실 시각화에 연결한다. 캐릭터의 이동이나 일하는 애니메이션만으로 실제 진행을 판정하지 않는다.
- 직원을 눌러 현재 업무·막힘·산출물·중단·재지시를 다룰 수 있어야 한다. 시험 HTML 하나의 고정 탭을 산출물 관리 체계로 유지하지 않는다.

## 남은 일 — 현황 기록이며 자동 실행 지시가 아님

1. Paperclip 기반 업무·실행·검수·산출물·PM 보고와 사무실 시각화를 한 화면에서 연결하는 완성도.
2. 현재 담당자와 원래 제작자·검수자·승인자의 기여 기록 분리.
3. 정기업무가 과거 기존 엔진과 새 Paperclip 경로 중 어디서 실행되는지 정리하고, 중복 실행 없이 이어지는 구조 확인.
4. 공급망 데모의 실제 도로 GIS·산업 문제 적합성·고객용 품질 검증.
5. Windows 실행기의 느린 Paperclip 시작 원인과 장애 복구 흐름.
6. 실제 폰 음성 정확도 및 최신 로그인 수정의 코드 포함 범위.
7. 상시 운영 서버 이전은 별도 목표로 수행해야 한다. 현재 요청은 채팅 작업 기록의 인계이며 DB·키·공개 주소 이전 완료로 보고하지 않는다.

## 앞으로 여러 PC에서 같은 맥락으로 작업하는 방법

- 이 클라우드 채팅과 이 저장소를 중심으로 작업한다. 다른 PC에서 같은 채팅을 열거나 새 클라우드 채팅이 이 문서와 `AGENTS.md`를 읽으면 보존된 요구사항·결정을 이어받는다.
- 새 채팅은 이 문서, `knowledge/company-charter.md`, `knowledge/daslab-team.md`를 읽고 현재 사용자 요청과 실제 선택된 코드 버전을 확인한다. 필요한 원본 세부 기록은 클라우드 사본이나 Git의 회차 목록으로 찾는다.
- 중요한 결정·실제 완료 결과·실패·남은 작업이 바뀌면 이 인계 기록 또는 그 기록이 가리키는 최신 문서를 같은 작업에서 갱신한다. 커밋·푸시가 승인된 작업은 코드와 인계 기록을 함께 원격에 저장한다.
- 다른 PC·클라우드 체크아웃에서 새로 작업할 때 원격의 변경을 확인하고, 깨끗한 체크아웃에는 빠른 병합으로 받는다. 작업 중인 변경을 덮어쓰거나 두 운영 DB 파일을 단순 동기화하지 않는다.
- 동기화 단위는 저장된 코드·기록이다. 모델의 계정 전체 기억이나 모든 PC의 네이티브 채팅을 실시간으로 동일하게 만드는 기능을 설정한 것은 아니다.
