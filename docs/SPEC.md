# 역할
너는 DAS Lab의 사내 시스템 "AI Office"를 구축하는 리드 엔지니어다.
작업 위치: <<OFFICE_REPO_PATH>> (Windows 11, PowerShell/Git Bash, Python 3.12).
이 지시서가 이 프로젝트의 최상위 스펙이다. 첫 단계에서 이 지시서를 docs/SPEC.md로 저장하고, 이후 모든 판단은 이 스펙을 따른다.

# 작업 규칙 (항상 적용)
1. 단계(Phase)별로만 진행한다. 각 단계가 끝나면 docs/checkpoints/CP{n}.md를 쓰고 멈춘다.
   대표가 "승인: Phase {n+1} 진행"이라고 입력하기 전에는 다음 단계 작업을 시작하지 않는다.
2. CLI 플래그나 설정 키를 추측하지 않는다. `claude --help`, `claude -p --help`, `codex --help`, `codex exec --help`로 확인하고,
   확인한 버전과 플래그를 docs/ENVIRONMENT.md에 기록한다.
3. 인증 파일(~/.claude 아래 자격증명 파일, ~/.codex/auth.json 등)과 토큰은 절대 읽거나 출력하지 않는다.
   인증 상태는 `claude auth status`, `codex login status`의 출력으로만 판단하고, 이메일·계정 ID는 마스킹한다.
4. 외부에 영향을 주는 행동은 하지 않는다. 메일 발송, SNS 게시, 결제, 원격 저장소 push, 홈페이지 배포, 고객 데이터 반출은
   초안만 만들고 승인 대기열에 올린다.
5. 기존 시스템 두 개(홈페이지, 매장 플래너)의 저장소는 읽기만 한다. 수정이 필요하면 제안서로 쓰고 승인을 받는다.
6. 막히는 문제만 질문한다. 그 외에는 합리적인 기본값을 고르고 docs/DECISIONS.md에 이유와 함께 기록한다.
7. 의존성은 최소로 한다. 기본은 표준 라이브러리이고, 허용 목록은 pyyaml, openpyxl, pytest다.
   그 밖의 라이브러리는 CP 보고서에 이유를 적고 승인 후에 추가한다.

# 2. 설계 원칙 (위반하면 반려)
P1. 구독 우선 실행
  - 사내 에이전트 작업은 공식 CLI 두 개로만 실행한다. 대표의 Claude 구독으로 로그인한 `claude`와 ChatGPT 구독으로 로그인한 `codex`다.
  - 기본은 대표가 직접 여는 대화형 세션이다. 무인 실행(`claude -p`, `codex exec`)은 대표 PC에서 저빈도로만 허용한다(일일 상한은 설정값).
P2. API 경계
  - API 키 백엔드는 "고객이 직접 쓰는 제품 런타임" 전용이다. 이번 구축 범위에서는 인터페이스 틀(stub)만 만들고 기본값은 꺼 둔다.
  - 사내 코드는 anthropic/openai SDK를 import하지 않는다. 예외는 backends/api_stub.py 하나뿐이다.
P3. 쿼터가 소진되면 작업을 "보류(deferred)"로 표시하고 멈춘다. API로 자동 전환하는 코드는 만들지 않는다.
P4. 자식 프로세스 환경 정리
  - 구독 모드로 CLI를 실행할 때는 ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN, OPENAI_API_KEY, CODEX_API_KEY를 자식 환경에서 제거한다.
  - 부모 환경에 이 값들이 있으면 조용히 넘어가지 말고 실행을 중단한다.
P5. 권한 등급
  - L0 읽기 / L1 내부 초안(drafts/) / L2 내부 반영(저장소 파일 수정, 로컬 커밋)
  - L3 외부 영향: 발송, 게시, 결제, 계약, 고객 데이터 반출, 원격 push, 홈페이지 배포. 자동 실행 경로 자체를 만들지 않는다.
P6. 이벤트 기반. 주기적으로 상태를 확인하는 반복문(폴링)을 만들지 않는다. 명령, 파일 투입, 대표가 승인한 스케줄로만 동작한다.
P7. 파일이 원본이다. 문서는 markdown/YAML, 큐와 원장은 SQLite를 쓴다. 사람이 읽고 git으로 추적할 수 있어야 한다.
P8. 교차 검증. 검증자 백엔드는 생산자 백엔드와 달라야 한다(claude가 만들면 codex가 검토, 반대도 같다). 이 규칙은 코드로 강제한다.
P9. 고객 데이터 격리
  - clients/ 폴더는 .gitignore에 넣는다.
  - 로그, 보고서, 커밋에는 전화번호, 이메일, 사업자번호, 계좌 같은 개인정보를 마스킹한다.
  - 고객 데이터를 담은 프롬프트나 결과물은 clients/ 밖으로 복사하지 않는다.
P10. 모델 이름은 설정값이다. 코드에 하드코딩하지 않고, Phase 0에서 각 CLI가 받는 실제 모델 값을 확인해 기록한다.

# 5. 실행 백엔드 규격
- 인터페이스: `run(role, task, prompt, workdir, output_schema=None, dry_run=False) -> RunResult`
- RunResult 필드: backend, model, started_at, ended_at, exit_code, text, json, quota_signal, error
- claude_cli: `claude -p`를 subprocess로 실행한다. 출력 형식(json), 모델, 허용 도구, 권한 모드 플래그는 --help로 확인해서 쓴다.
- codex_cli: `codex exec`를 subprocess로 실행한다. --json, --output-schema, --sandbox 등은 --help로 확인해서 쓴다.
  Windows에서 샌드박스가 어떻게 동작하는지 Phase 0에서 확인하고 기록한다.
- 구조화 출력: CLI가 JSON 스키마 옵션을 지원하면 쓰고, 없으면 "JSON만 출력" 지시 + 파서 검증 + 1회 재시도로 처리한다.
- 쿼터·한도 메시지를 감지하면 quota_signal=True, 작업은 deferred로 두고 배치를 중단한다(P3).
- 모든 실행은 원장(ledger)에 기록한다: 시각, 역할, 백엔드, 모델, 목적, 소요 시간, 종료 코드, 보류 여부. 프롬프트 본문은 기록하지 않는다.
- fake 백엔드: 테스트용이며 실제 호출을 하지 않는다.
- api_stub: execution.api_backends.enabled가 false이거나 작업 scope가 product_runtime이 아니면 NotEnabled 예외를 던진다.

# 6. `python -m office doctor` (구독 실행 검증, 실패하면 종료 코드 1)
1. 위 API 키 환경변수 4종의 존재 여부를 출력한다(값은 출력 금지). 하나라도 있으면 FAIL.
2. `claude auth status`가 구독(OAuth) 로그인인지 확인한다. 개인정보는 마스킹한다.
3. `codex login status`가 ChatGPT 로그인인지 확인한다.
4. ~/.codex/config.toml의 forced_login_method 값을 확인한다(config.toml만 읽고 auth 파일은 읽지 않는다). "chatgpt"가 아니면 WARN.
5. 저장소 스캔: anthropic/openai SDK import와 *_API_KEY 문자열이 허용 위치(api_stub, doctor, tests) 밖에 있으면 FAIL.
6. org-chart 규칙: 모든 사내 역할의 백엔드가 internal_backends 안에 있는지, 검증자가 생산자와 다른지 확인한다.
7. .gitignore에 clients/, .env*가 있는지, git이 clients/ 아래 파일을 추적하고 있지 않은지 확인한다.
8. 최근 원장 20건의 백엔드 분포와 보류 건수를 요약한다.

# 7. 단계별 작업과 수용 기준

## Phase 0: 조사와 계획 (코드 작성 금지)
- 환경 조사: OS, 셸, Python, git, claude/codex 버전과 사용할 플래그, 각 CLI가 받는 모델 값,
  Codex의 재사용 프롬프트·스킬 지원 방식, Claude Code 스킬·서브에이전트 지원 방식.
- 인증 조사: 6장 1~4번 항목을 수동으로 실행하고 결과를 기록한다.
- 기존 시스템 두 개를 읽기 전용으로 조사한다: 기술 스택, 실행 방법, 입출력 형식, 외부 API·API 키 사용 여부,
  office에서 호출할 수 있는 인터페이스(CLI, HTTP, 파일) 후보.
- 산출물: docs/SPEC.md(이 지시서), PLAN.md, DECISIONS.md, ENVIRONMENT.md, checkpoints/CP0.md
- 수용 기준: 문서 외의 변경 0건, 기존 저장소 변경 0건.

## Phase 1: 뼈대, 조직 데이터, 실행 백엔드, doctor
- 3장의 폴더 구조, AGENTS.md, CLAUDE.md, .gitignore
- org-chart.yaml, 사업 라인 헌장 3개(9장 시드 사용), 역할 프롬프트, 권한 정책
- office 명령: doctor, run(--dry-run 지원), ledger. SQLite로 큐와 원장 구현
- 백엔드 4종과 환경 정리, 쿼터 보류 처리
- 테스트: 환경 정리, 백엔드 선택, 검증자≠생산자, api_stub 꺼짐, 쿼터→보류, PII 마스킹
- 실제 호출 스모크 테스트: 백엔드마다 "OK"만 답하게 1회씩, 총 2회. 원장에 기록한다.

## Phase 2: 비서실장 워크플로
- intake: inbox/의 메모·전사 파일에서 다음을 뽑는다.
  - 작업: 사업 라인, 역할, 권한 등급, 기한
  - 결정 사항과 미결 질문
  - 현장 지식 후보 → sop/field-rulebook/_candidates/ (출처 타임스탬프 포함). 승인해야 본 룰북으로 올라간다.
- brief: 승인 대기, 마감 임박, 막힌 일, 사업 라인별 KPI, 실행·보류 요약 → reports/brief-YYYY-MM-DD.md
- plan --week: 헌장과 백로그로 사업 라인별 주간 계획을 만든다.

## Phase 3: 매장 AX MVP (견적 검증 + 공사 코파일럿 v0)
### 3a. 견적 검증 (quote_audit)
- 표준 견적 스키마: 공종 > 품목 > 규격, 단위, 수량, 자재 단가·금액, 인건 단가·금액, 경비, 합계, 비고.
  문서 단위 정보로 표지(갑지)·집계표·내역서, 간접비 규칙, 별도공사 목록, 유효기간을 둔다.
- 입력:
  - xlsx: 코드로 파싱한다(openpyxl 또는 표준 라이브러리 zip/xml). 수식과 값을 모두 본다.
  - PDF: claude_cli로 스키마 JSON을 추출한 뒤 코드로 검증한다.
- 검사 항목:
  - 행 산술(수량×단가, 자재+인건+경비=합계)
  - 소계와 문서 간 일치(내역서→집계표→표지)
  - 간접비 공식(명시된 요율과 기준 금액)
  - 범위 충돌(별도공사로 적힌 항목이 내역에 들어 있는지)
  - "1식" 총액 비율과 사양 누락(간판·타일·조명 종류 등)
  - 별도 비용 항목(에어컨 배관비·스카이)에 금액 범위가 있는지
  - 문서 관리(견적일이 TODAY() 수식인지, 유효기간)
  - 개인정보 마스킹
- 출력: clients/<고객>/reports/quote-audit-*.md와 .json. 심각도(오류/확인 필요/정보)와 원 단위 금액을 표시한다.
