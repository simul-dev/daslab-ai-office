## 당시의 결정과 작업 — 참고용

아래의 ‘현재’, ‘아직’, ‘미구현’, ‘승인 미확인’ 등은 원래 기록 시점의 상태다. 최신 프로젝트의 현황이나 진행 제한으로 해석하지 않는다.

- 대표는 자연어로 지시한다. 내부 목표·우선순위·난이도·절차·완료 기준은 담당자가 정리한다. 요약 보고를 먼저 보여주며 JSON과 근거는 선택적으로 펼친다.
- 목표 조직은 대표 → 전용 비서 → 사업별 PM → 전문 리드 → 필요한 임시 에이전트다. 현재 DAS Lab이 우선이다. 현재 구현의 초기 라우팅은 코드 규칙이며 다중 PM 자율 협상·상시 일정·임시 직원 자동 생성은 미구현이다.
- 2026-09-26 별도 v0.4 사양 작업은 CP0 조사·문서까지다. Phase 1 진행 승인은 확인되지 않았다. 이후 9월 29–30일 직접 요청으로 구현한 조직 엔진을 v0.4 전체 완료와 혼동하지 않는다.
- 조직 엔진은 직원별 기억·미션·개입·시도·결과를 SQLite에 보존하고 UI/SSE로 연결한다. 구독용 공식 Codex CLI를 쓰며 유료 API로 자동 전환하지 않는다.
- 음성은 사용자가 버튼으로 시작하는 선택 입력이다. 원음·화자 특징은 기기에서 처리한다. 기기별 음성 등록과 실제 정확도는 별도 검증 대상이다.
- PM/R&D에는 내부 조직 UI 별도 작업본 수정 권한을 연결했다. 운영 DB·설정·공개 홈페이지 수정 권한으로 확대하지 않는다.
- R&D 디자인 실행은 289.17초, HTML/CSS 수정 및 정적 검사 후 읽기 전용 미리보기로 전달됐다. 감독자의 브라우저 확인과 직원 자체 자동 브라우저 검증은 구별한다. 운영 디자인에는 아직 적용하지 않았다. 보존 소스: `design-previews/20260930/`.
- 이전 로컬 검증 보고: Python 140개 통과·2개 건너뜀, Node 음성 정책 16개 통과. 이번 동기화 준비에서 앱 검사를 재실행한 결과가 아니다.
- 첫 사업 미션인 데모 고도화·홍보는 완료로 처리하지 않는다. 정기 게시·계정 연결·성과 측정도 자동 활성화된 것으로 취급하지 않는다.

## 향후 비교가 필요할 때 사용할 수집 방법

아래는 비교 방법에 관한 참고다. 이 과거 버전에서 개발을 재개하거나 최신 환경으로 병합하라는 지시가 아니다. 최신 기준본을 확인한 뒤 필요한 변경만 개별 검토한다.

각 PC 저장소에서 `python scripts/collect_sync_inventory.py --label home` 또는 `--label office`를 실행한다. 기본 결과는 저장소 밖 사용자 지정 경로 또는 OS 임시 폴더의 JSON이다. HEAD·브랜치·변경 파일 목록만 수집하며 코드 내용·인증 정보·DB·직원 기억은 담지 않는다. 각 결과로 분기/미커밋 차이를 먼저 확인한다.

코드 차이가 있으면 PC별 별도 브랜치로 보존해 비교하고 충돌을 해결한다. 서로의 미커밋 변경 위에 pull/reset을 실행하지 않는다. Git 제외 파일은 목록 확인 후 필요한 자료만 별도 전달한다.

직원 기억은 문서와 달리 `data/organization.sqlite3`의 운영 데이터다. 두 PC의 DB를 단순 파일 덮어쓰기로 합치지 않는다. 각 서버의 업무를 멈추고 SQLite backup API 등으로 일관된 백업을 만든 뒤, 어느 PC가 기준인지와 직원/미션/이벤트 충돌을 확인한다. DB를 운영에 복원하는 작업은 이번 준비에서 수행하지 않았다. OneDrive 안의 같은 SQLite를 두 PC에서 동시에 열지 않는다.

음성 모델·vendor는 설정과 설치 스크립트로 다시 준비한다. 기기 음성 프로필·Codex 로그인·토큰·환경파일은 코드 동기화와 분리한다.

이번 준비 범위는 과거 코드 스냅샷 식별, 과거 작업 참고 기록 보존, 선택적으로 사용할 PC별 변경 상태 수집 도구 마련이다. 최신 개발 인수인계, 작업 재개, 자동 양방향 동기화 또는 전체 메모리 이관 완료를 뜻하지 않는다.
