• P1 안전재고 확대: OTIF 94.05%, 총비용 133.58 CU

둘째 주
- D8: 동일한 발행 조건이 갖춰지면 Threads 초안을 게시한다. LinkedIn과 문안·게시 시점이 다르므로 엄밀한 채널 효과 실험으로 해석하지 않는다.
- D9–D11: 승인된 응대 담당이 들어온 질문의 문제·역할·상담 의사를 정리한다. 유효문의 판단은 영업 역할이 실제 문의 내용을 검토해 기록한다. 공개 데모와 계측이 준비된 경우에만 유입·실행 집계를 시작한다.
- D12–D13: 각 게시물의 게시 후 경과시간이 같은 구간을 우선 비교한다. 전체 기간 실적도 별도로 보존한다. 조회수만 높고 업무 질문이 적으면 문제 제시 문장을, 문의는 있으나 실행을 원하지 않으면 데모 설명과 접근 장벽을 다음 수정 후보로 정한다.
- D14: PM에 게시 여부, 채널별 유입, 완료 실행, 유효문의, 계측 불가 항목과 실제 질문을 보고한다. 소수 반응으로 우열을 확정하지 않고 다음 실험에서 바꿀 메시지를 선택한다.

선행조건 미충족 시: 계정·권한이 없으면 게시하지 않고 미게시 사유를 기록한다. 공개 데모가 없으면 유입·실행 전환 지표는 해당 없음으로 두고 문의만 관찰한다. 남은 기간을 임의의 성공 숫자로 채우지 않으며, PM이 연결 조건과 일정 조정을 판단한다.

## 유입·데모실행·유효문의 측정안

목적은 제조·유통 의사결정자의 관심이 실제 정책 비교와 구체적인 상담으로 이어지는지 관찰하는 것이다. 현재 게시·계측·문의 실적은 미집계이며 0으로 대체하지 않는다. 수치 목표나 예상 전환율은 근거가 없어 설정하지 않는다.

측정 단계
1. 게시 및 반응: 실제 게시 식별자·시각·채널·문안 버전을 기록한다. 노출·도달·댓글은 계정에서 확인 가능한 정의와 조회 시각을 함께 보존한다. 조회·좋아요 자체를 데모 유입이나 유효문의로 세지 않는다.
2. 유입: 공개 데모와 계측이 생긴 뒤, 데모 페이지가 실제 열린 유효 세션을 demo_view로 기록한다. 채널·콘텐츠 식별자를 전달할 수 있을 때만 해당 채널 유입으로 귀속한다. 지금은 링크가 없으므로 데모 유입을 측정할 수 없다. URL은 생성하지 않는다.
3. 데모실행: 정책 계산 요청 시 demo_run_start, 정상 계산과 결과 표시까지 끝났을 때 demo_run_complete, 실패 시 demo_run_error를 기록하도록 제안한다. 시작 클릭을 완료 실행으로 세지 않는다. 이벤트 구현·설치는 미수행이다.
4. 유효문의: 제조·유통의 재고/공급망 의사결정에 관여하는 역할, 구체적인 재고·납기·발주 문제, 후속 대화 의사가 실제 문의에서 확인된 경우로 정의한다. 확인이 부족하면 확인 대기, 일반 감상·광고·스팸이면 비유효로 분류한다. 단순 관심 댓글을 자동 승격하지 않는다.

권장 기록 항목
- 분석 이벤트: 발생 시각과 시간대, 익명 세션 식별자, 이벤트명, 콘텐츠 식별자, 유입 채널, demo_version, scenario_id, run_id, 실행 성공·오류 상태.
- 문의 기록: 제한 접근 문의 식별자, 접수일, 실제 접수 경로, 확인된 역할·문제·후속 의사, 판정·판정자·판정일. 분석 이벤트에 연락처나 고객 원자료를 넣지 않는다.
- 귀속: 전달된 콘텐츠 식별자가 있으면 관측 귀속, 본인이 유입 경로를 말하면 자기보고 귀속, 둘 다 없으면 미상으로 둔다. 채널에서 직접 온 문의는 데모실행을 거쳤다고 가정하지 않는다.

중복·제외 규칙
- 내부 담당자·QA·자동화 테스트는 테스트 표식으로 분리하여 성과 집계에서 제외한다.
- 동일 run_id의 중복 완료 이벤트는 한 번만 센다. 재실행 건수와 실행 세션 수는 따로 보고한다.
- 동일 인물의 같은 상담 건이 댓글과 다른 접수 경로에 반복되면 유효문의는 하나로 합친다. 회사 수는 별도 보조 지표로 기록한다.
- 채널을 넘나든 익명 이용자는 확실한 연결 근거 없이 같은 사람으로 합치거나 사람 수로 보고하지 않는다.

계산식
- 유입→실행 전환율 = 정상 실행 완료 세션 수 / 유효 데모 방문 세션 수 × 100.
- 실행 성공률 = 중복 제거 정상 완료 run_id 수 / 중복 제거 시작 run_id 수 × 100.
- 문의 유효율 = 유효문의 건수 / 중복 제거 전체 문의 건수 × 100.
- 실행→유효문의 전환율 = 실제 연결이 확인된 유효문의 발생 실행 세션 수 / 정상 실행 완료 세션 수 × 100. 연결 수단이 없으면 산출 불가로 기록한다.
- 분모가 0이거나 데이터가 없으면 비율은 해당 없음 또는 미집계로 표시한다. 서로 연결되지 않은 문의와 실행을 나눠 전환율로 제시하지 않는다.

평가 원칙: 게시 후 같은 경과시간의 관측치를 비교하고 원시 건수·분모·누락을 함께 보고한다. 채널별 고객 구성과 게시 시점이 다르므로 인과효과나 바이럴 재현성을 주장하지 않는다. 문의·상담과 계약·매출은 별도 단계로 관리한다.
