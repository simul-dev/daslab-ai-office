## 직접 읽어 확인한 산출물

첫 MVP는 **공사 견적 비교표 작성** 하나로 제안되었다. 대표의 배경 설명에 근거한 문제와 추가 확인이 필요한 가정을 분리했다. 입력 견적·공사 기준·근거 위치, 비교표·금액 점검·확인 사항, 실제 고객 업무 검증 계획과 완료 기준, 역할별 후속 작업이 포함되어 있다.

문서를 직접 읽어 정량 절감률·시장규모·고객 인터뷰 결과를 만들어내지 않았고, 고객 검증을 이미 수행했다고 주장하지 않았음을 확인했다. 이는 구현 담당의 문서 점검이며 **대표 승인이나 실제 고객 검증을 대체하지 않는다**. 업무는 `review`로 남아 있으며 `completed`로 바꾸지 않았다.

CLI 이벤트 중 Code Mode host를 끈 데 따른 도구 비활성 안내가 한 번 있었다. 실제 외부 도구 실행 없이 최종 구조화 응답과 완료 이벤트가 기록되었고 프로세스는 정상 종료했다. `stderr.log`는 비어 있다.

## 저장·웹 검증

- 실제 서버를 종료 후 재시작했다. 재시작 전후 API 결과에서 업무·계획·실행·이벤트·결정 값이 모두 일치했다.
- API로 다시 읽은 산출물/기록 10개 모두 저장된 SHA-256과 일치했다.
- Chromium에서 실제 Codex 연결 표시, 검토 필요 업무 상세, 보고서 미리보기, 시험 업무 입력 불러오기, 상태 필터, 모바일 가로 넘침 없음, JavaScript 오류 없음을 확인했다.
- 화면과 확인 기록: `test-results/office-desktop.png`, `office-report.png`, `office-mobile.png`, `browser-check.json`, `restart-check.json`. 이 폴더는 로컬 검증용으로 Git에서 제외한다.

## 자동 회귀 검증

`python -m unittest discover -s tests -q`: **40개 통과**. `node --check static/app.js`: 통과.

자동 테스트는 실제 AI를 호출하지 않는다. 테스트용 provider 및 로컬 Python 프로세스로 다음을 확인했다.

- 영속 저장, 중단 작업 실패 복구, 단일 동시 실행, 업무별·일별 제한, 한국 시간 날짜 경계
- 승인·반려 상태 전이, 명시적 재실행과 과거 기록 보존, 검토 의견의 재실행 입력 반영
- 파일 변조·읽기 오류, 누락·빈 산출물, 완료 주장만 있는 응답, 근거 기준 불일치의 검증 실패
- 실행·검증 중 취소, 이전 실행 정리와 새 실행의 경쟁 상태
- API 키·provider 환경변수 제외, ChatGPT 외 인증 거부, 인증 불가 시 실행 차단
- Windows Job이 실제 로컬 시험 프로세스를 시간 초과·취소 시 종료함. 큰 stdin 입력으로 파이프가 막힌 경우에도 제한 작동
- 로컬 Host·Origin·요청 헤더 검증 및 오류 메시지의 비밀정보 노출 방지

## 검증 범위 밖과 다음 작업

- 실제 고객 인터뷰, 실제 견적 자료 검증, 사업 효과 측정은 미실시.
- PM/Reviewer는 코드 구현체다. AI Planner/Reviewer와 Claude Worker는 인터페이스만 준비되어 있고 연결하지 않았다.
- 응답 스키마와 코드 검증 규칙은 첫 MVP 제안 업무를 중심으로 구성했다. 다른 업무 종류를 늘릴 때 결과 계약을 확장한다.
- 임의 코드 실행·저장소 수정, 사내 다중 사용자 인증, 외부 발송·구매·운영 배포는 미연결.
- 실행 횟수·경과 시간은 직접 측정한다. 비용·잔여 계정 사용량은 확인하지 않으며 추정값을 표시하지 않는다.
- 다음은 대표가 보고서와 완료 기준을 검토해 승인/반려하고, 승인한다면 실제 비교 견적과 담당자 검증 기준을 확보하는 것이다.
