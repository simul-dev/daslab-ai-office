# DAS Lab 정기 운영 · 2026-09-30

대표의 직접 지시로 직원들이 새 업무만 기다리지 않고 정기적으로 기술·시장 조사, 데모 구현, 콘텐츠·제안 준비를 수행하도록 연결했다. 기존 미션과 UI 개발 경로를 보존하고 `daslab-growth` 프로젝트를 분리했다.

## 담당과 실행

`config/standing.json`은 R&D·기획마케팅·영업의 책임, 첫 공급망 우선순위, 정기 주기를 정의한다. 첫 회차와 월요일에는 R&D가 DES·ABS/ABM·SD 등을 고객 문제에 맞춰 조사한다. 완료된 이전 회차가 있는 다른 평일에는 R&D가 격리 데모를 구현한다. 마케팅은 채널·콘텐츠·검토·측정안, 영업은 공개 기업 자료·기회 적합성·맞춤 제안 초안을 만든다. 세 결과가 끝나면 PM 통합 검토를 실제 미션으로 배정한다.

배정은 현재 설정과 코드에 기반한다. PM 검토는 직원 결과를 평가하는 실제 구독 실행이다. 이를 여러 사업을 스스로 운영하거나 임시 직원을 만드는 범용 자율 PM으로 표현하지 않는다. 비서의 신원·기억은 남기고 현재 화면·기본 수신자는 PM을 대표에게 직접 연결한다.

`office/standing.py`는 `settings.standing_operations_v1`에 회차와 정확한 요청을 저장한다. 날짜·담당별 요청 ID를 재사용해 중복을 막는다. 기존 진행·정지·실패 회차가 있으면 새 회차를 쌓지 않는다. 실제 실행 횟수와 대기 예약을 함께 세며 하루 전문 업무 세 개·PM 검토 한 개를 상한으로 한다. 재개한 직원의 결과가 달라지면 오래된 PM 보고를 최신 검토로 인정하지 않는다.

## 실제 도구와 검증

- 공개 조사: `config/research.json`의 직원만 `research`로 실행한다. 내장 검색과 이를 제공하는 code-mode host만 켜며 셸·파일 탐색·앱·발행은 끈다. 기존 ChatGPT 구독을 사용한다. 실제 CLI 검색 완료 이벤트가 있어야 조사 완료 보고를 허용한다. 검색 이벤트는 출처의 진실성이나 사업 성과의 증명이 아니다.
- 데모 구현: `config/prototypes.json`의 PM·R&D가 실행별 `workspace`에서 README·HTML·CSS·모델·화면 코드·모델 검사 초안을 수정한다. 현재 모델 계약은 공급망 DES 초안이다. 공식 홈페이지·운영 UI·DB를 수정하지 않는다. 패키지 설치와 외부 네트워크도 허용하지 않는다.
- 데모 검사: 파일 범위·링크·외부 의존성·문법과 변경 파일을 검사한다. 호스트에서 생성된 테스트를 실행하지 않는다. 분리된 실제 브라우저에서 재고·주문 보존식, 음수/비유한 값, 동일 입력 재현성, 수요 0·공급 0·용량 증가, 화면 입력 반영과 두 화면 너비를 검사한다. 검수가 실패하면 막힘으로 남는다. 결과 해시를 고정한 읽기 전용 로컬 미리보기를 제공한다.
- 모델 기본 검사는 현장 타당성이나 고객 효과 검증이 아니다. 3D 에셋·현장 데이터·다른 방법론·실제 SNS 발행·연락·입찰 제출은 별도 결과와 연결이 필요하다.
- 동시에 유지하는 데모 미리보기 서버는 16개다. 오래 사용하지 않은 서버만 닫으며 파일·검증 이력은 남긴다. 앱의 원래 데모 링크를 다시 열면 고정된 해시를 확인하고 미리보기를 재생성한다.

## 예약과 화면

현재 대화에 연결된 Codex heartbeat를 평일 오전 9시(Asia/Seoul)로 등록한다. 업무를 이어갈 실제 주체는 이 외부 예약이며 서버 모듈 자체에는 타이머나 OS cron을 만들지 않았다. 앱과 PC가 켜져 있어야 하며 다른 PC에 저장소를 복사했다고 그 PC에 일정이 설치되는 것은 아니다. 일정 ID 등록 기록은 DB에 남기며 실시간 스케줄러 상태를 보증하지 않는다.

조직 화면의 **팀 정기 업무**에서 지금 실행, 신규 배정 정지·재개, 직원 결과와 PM 검토를 확인한다. 정기 배정 정지는 이미 실행 중인 미션을 취소하지 않는다. 기존 미션 제어는 각 상세 화면에서 계속 사용한다.

API는 기존 localhost·Origin·JSON·`X-DAS-Office: 1` 검사를 따른다. GET `/api/org/standing`, POST `/api/org/standing/tick`, POST `/api/org/standing/pause`, POST `/api/org/standing/schedule`은 각각 상태·한 회차 진행·신규 배정 제어·실제 외부 예약 등록 기록을 다룬다. 읽기 전용 스냅샷은 업무를 시작하지 않는다.

## 기대 수준과 보고

`knowledge/quality-bar.md`의 대표 지시와 성공적으로 저장한 업무 추가 지시는 다음 실행에 전달한다. 개별 피드백은 `owner_statement`, 출처 미션, 시각과 당시 범위를 보존한다. AI가 추정한 선호를 대표 지시로 만들거나 모델 가중치를 학습했다고 표현하지 않는다.

현재 미션의 미완료는 `remaining`, 다음 단계는 `next_actions`, 상위 목표와 증거의 한계는 `limitations`에 구분한다. 구조 검사에 걸린 보고는 완료로 넘어가지 않는다. 실패한 원문과 검색·시도 기록은 보존한다. 실제 결과·실패·대표 결정이 생긴 경우에만 외부 예약이 알리고 변화 없는 상태에서는 반복 보고하지 않는다.

실제 초기 검수에서 발견한 서식 오류는 원문을 덮어쓰지 않고 `report-corrections`에 별도 사본과 검토 이유·이전/이후 해시를 남겨 바로잡는다. 후속 업무 필드 구분 또는 완료 기준·근거 경로 형식만 제한적으로 수정할 수 있고, 본문·상태·미확인 판단을 임의로 승격하지 않는다. 수정 사본도 기존 엄격 검사를 통과해야 한다. 새 출력은 `C1` 같은 안전한 기준 ID를 쓰고 실행기가 원래 완료 기준으로 정확하게 복원하며 원시 출력도 보존한다.

일일 한도는 모델 작업 횟수다. provider가 출력 스키마를 생성 전에 거부했고 실제 모델·도구 항목이나 결과가 전혀 없다는 원본 이벤트가 확인된 경우만 작업 횟수에서 제외한다. 거부 시도 이력과 미션별 재시도 제한은 유지한다. 실제 작업 실패·구독 한도·도구 실행은 제외하지 않는다. 이는 구독 과금·잔여량 판정이 아니다.

대표가 현재 작업을 계속하도록 지시했지만 내부 일일 한도를 이미 소진한 경우, 운영자가 서버 시작에 `--extra-runs-today 1..30`을 명시해 해당 실행의 한국 날짜에만 제한된 추가 실행을 허용할 수 있다. PM·조사·개발·재검수의 다단계 검증을 위한 운영 옵션이다. 설정 파일·사용 이력·미션 재시도 횟수는 바꾸지 않는다. 시작 기록을 남기며 날짜가 바뀌거나 옵션 없이 재시작하면 기본 한도를 쓴다. 직원 판단으로 자동 활성화되지 않고 유료 API로 전환하지 않는다.

정상 종료한 데모가 후처리 검사에서 막혔을 때는 `POST /api/org/missions/<id>/recheck-prototype`로 같은 파일을 재검사할 수 있다. 완료된 원본 직원 실행·보고서 검증·최신 실패 미션·파일 해시를 확인하고, 정책 비교를 포함한 독립 브라우저 검사를 다시 수행한다. 실패 이력과 원문은 보존하고 새 `prototype-rechecks` 영수증만 추가한다. 첫 정적 실패로 원본 소스 해시가 없던 경우 첫 재검수의 스냅샷임을 명시하며, 이후 재검수도 그 해시를 유지한다. 직원 재호출이나 실행 횟수 초기화는 없다. 성공한 검증 파일은 다음 개발의 시작점과 읽기 전용 미리보기에 연결된다.

## 최초 실제 회차 확인 · 2026-09-30

후속으로 완료 보고서의 재개 요청이 내부 한도 때문에 실제로 시작되지 않았는데 기존 결과가 화면에서 숨겨지는 문제를 수정했다. 한도 검사에서 거부할 재개는 이제 결과를 이동하기 전에 중단한다. 이미 발생한 미실행 재개는 `/recover-report`의 `kind: restore_unstarted`, 정확한 `expected_attempt_id`, 검토 이유로 제한적으로 철회할 수 있다. 원본·교정 보고 해시, 같은 `previous_result`, 추가 지시·새 시도 없음, 실제 검색 기록, 보고 이후 재개→일일 보류 이벤트만 존재하는 조건을 검증한다. 원래 시도·실패·검색·재개·한도 기록은 보존하고 별도 복원 근거를 남긴다. 실제 세 보고를 복원한 뒤 기존 PM 검토 근거와 정확히 일치해 정기 회차는 다시 완료 상태다.

대표의 추가 진행 지시에 따라 공급망 정책 데모를 실제 개발·독립 검사하고 마케팅·영업 문안 및 PM 검토까지 실행했다. [후속 결과](reports/2026-09-30-policy-demo/README.md)와 [데모 계약·검증](SUPPLY-CHAIN-POLICY-DEMO.md)에 보존한다. 감독자가 배정한 별도 후속 미션이며 첫 조사 회차 보고를 새 데모 개발 실적으로 바꿔 쓰지 않는다.

기존 Codex 구독으로 세 전문 직원과 PM 검토를 실제 실행했다. 전문 직원의 검색 완료 이벤트는 R&D 4회, 마케팅 5회, 영업 3회다. R&D는 입고 지연의 안전재고·긴급운송 비교 설계, 마케팅은 LinkedIn·Threads 각 두 게시물 초안과 시연 구성, 영업은 기업 두 곳의 비교와 CJ대한통운 맞춤 제안 초안을 제출했다. PM은 펌프 데모 실행 증거 부족과 공급망 모델·영업 제안 범위 차이를 실제 보고에서 지적하고 다음 검수 기준을 정리했다. 회차 종료는 이 조사·초안·검토의 종료이며 제품 개발·공개·영업 성과 완료가 아니다.

실제 실행에서 발견한 보고 형식 오류의 원문·실패 기록은 보존하고 제한된 형식 교정으로 복구했다. PM의 첫 요청은 출력 스키마가 생성 전에 거부되었고, 안전한 기준 ID로 수정한 뒤 같은 미션을 재개하여 구조 검사를 통과했다. 이 재실행은 132.14초였다. 별도로 개발자가 기본 DES 시드에 수행한 실제 브라우저·모델 검사 21항목은 통과했지만, 이를 직원이 완성한 데모로 기록하지 않는다. 다음 평일 회차의 R&D 실행부터 기존 조사와 PM 결과를 전달해 실제 데모 파일 개선을 수행한다.

## 실제 정기 회차 · 2026-10-01

오전 9시 heartbeat가 기존 서버의 정확한 worktree·data 명령, 8772/8774 loopback listener, `data/server.lock`의 잠금과 직원 실행 0건을 확인한 뒤 `/api/org/standing/tick`을 한 번 호출했다. 기존 19개 미션에 R&D·마케팅·영업과 후속 PM 검토 4개가 추가됐다. 중복 회차나 별도 대체 미션을 만들지 않았고 기존 구독과 하루 10회 한도를 유지했다.

- 마케팅 `edb05cfe228a49be87f822310fb42058`: 실행 `87cbff938aea406b9edc2702bd66877c`, 225.97초, 실제 웹검색 완료 3건. LinkedIn·Threads 각 2개 게시물 초안, 60초 시연 영상 구성, 검토·측정안을 제출했다. 공식 채널 자료의 날짜·기능 범위를 독립 대조했다. 영상 제작·게시·반응 측정은 하지 않았다. 공개 데모 버전·링크·표현 근거 확인이 남아 부분 달성을 유지했다.
